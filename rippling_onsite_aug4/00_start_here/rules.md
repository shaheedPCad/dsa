# Rules

## No Skeleton Shortcut

For every problem, write everything yourself:

- imports
- class line, if required by the platform
- method definition
- helper definitions
- test cases
- complexity explanation

## Done Means

A problem is done only when you can:

- restate it clearly
- name the pattern
- explain brute force
- explain the optimized invariant
- code it without looking
- trace one normal case
- trace one edge case
- state time and space complexity

## Debugger Rule

Use the debugger after you have manually traced at least one test case. In the
interview, ask before running code, and narrate what you expect to see.
